# 저장장치 관리: dump 자동 삭제

## 적용 범위

- WebService가 기본 60초 간격으로 지정 폴더의 디스크 가용 공간을 점검합니다. 서비스 재시작 후 첫 점검은 60초 뒤입니다.
- 자동 삭제는 기본적으로 꺼져 있습니다. 서버 설정의 허용 폴더와 DB 삭제 대상 기준의 폴더가 일치해야 합니다.
- 허용 폴더 **바로 아래의 일반 `.dump` 파일만** 자동 삭제합니다. 하위 폴더, 링크, 영상, 로그, `.dump.part`는 제외합니다.
- 기존 AUTO 로그 삭제 기준이 있어도 `.log` 파일은 이 모듈에서 삭제하지 않습니다.
- `tb_ka_data`, `tb_dcs_data`, 영상 파일 및 전송 이력은 삭제하거나 변경하지 않습니다.
- 수동 삭제는 기존 선택 파일 삭제 기능을 유지하며, 자동 삭제의 dump 제한을 적용하지 않습니다. 수동·자동 모두 로그 5년 보관 보호를 적용합니다.

## 운영 설정

**Ka 수신 폴더의 dump는 수신 완료 신호입니다.** 수신 처리·재처리에 필요한 파일을 정리하지 않도록, 처리 완료 후 보관하는 전용 폴더를 지정하십시오. 경과일만으로 Python 처리 완료 여부를 판정하지 않습니다.

1. 전용 폴더를 준비합니다. 예: `D:/deleteTest/dump_cleanup`. 드라이브 루트, 상대 경로, 링크 경로는 사용할 수 없습니다. WebService 실행 계정만 폴더 구조를 변경하도록 OS 권한을 제한하십시오.
2. 저장장치 관리 화면의 **삭제 대상 기준**에 다음 값을 등록합니다.

| 항목 | 값 |
| --- | --- |
| 기준명 | 처리 완료 dump 정리 |
| 삭제 방식 | AUTO |
| 대상 유형 | RULE |
| 기준 경로 | D:/deleteTest/dump_cleanup |
| 파일 패턴 | *.dump |
| 확장자 | dump |
| 최소 경과일 | 7 |
| 최소 크기 | 공란 또는 0 |
| 사용 | 체크 |

3. **보관 기간 정책**에서 확장자 `dump`, 보관 기간 `7일`, 사용 체크를 설정합니다. 자동 삭제는 보관 기간 정책이 없거나 꺼져 있으면 수행하지 않습니다. 삭제 대상의 최소 경과일과 보관 기간 중 **긴 기간**을 적용하며, 최소 1일을 보관합니다. `FILE` 유형은 기준 경로를 폴더로 지정하고 파일 패턴에 정확한 파일명(예: `test001.dump`)을 입력합니다.
4. **가용 공간 기준**에 같은 폴더를 등록합니다. 예: 주의 80%, 위험 90%, 최소 여유 10GB, 사용 체크. 정확한 폴더 기준 → 드라이브 루트 기준 → ALL 공통 기준 순으로 하나를 선택합니다. 선택된 기준이 꺼져 있으면 정리하지 않습니다. 상위 임의 폴더 정책을 상속하지 않습니다.
5. WebService 실행 환경에 아래 값을 지정하고 재시작합니다. IDE에서는 실행 구성의 환경 변수에 입력합니다. PowerShell에서는 **서버를 시작할 동일 창**에 지정합니다.

```powershell
$env:HDCS_STORAGE_CLEANUP_ENABLED = 'true'
$env:HDCS_STORAGE_CLEANUP_DIR = 'D:/deleteTest/dump_cleanup'
$env:HDCS_STORAGE_CLEANUP_INTERVAL_MS = '60000'
```

서버 설정은 `src/main/resources/application.yml`의 `hdcs.storage.cleanup`에 있습니다. 회당 최대 삭제 개수는 `max-files-per-run` 기본 100개, 상한 1000개입니다. DB의 세 정책은 매 점검마다 다시 조회하므로 저장 후 재시작할 필요가 없습니다. 서버 허용 폴더 및 활성화 설정 변경은 재시작해야 합니다.

기존 저장장치 테이블을 그대로 사용하므로 이 기능을 위한 새 테이블은 없습니다. 이벤트 저장을 위해 앞서 제공한 `src/main/resources/sql/log_audit_retention_postgresql.sql`은 적용되어 있어야 합니다. 운영 DB에 초기화용 `schema.sql`을 실행하지 마십시오.

## 처리 조건과 중단

- 사용률이 주의 기준 이상이거나, 가용 공간이 최소 여유 공간 이하일 때 정리를 시작합니다. 위험 기준은 기존 화면의 위험 표시 기준입니다.
- 모든 정책 조회 성공 후, 조건에 맞는 파일을 수정 시각이 오래된 순서로 삭제합니다. 패턴, 확장자, 최소 크기, 보관 기간을 모두 충족해야 합니다.
- 파일마다 공간을 다시 확인하며, 사용률이 주의 기준 미만이고 가용 공간이 최소 기준을 초과하면 중단합니다. 공간 부족이어도 보관 기간을 줄이거나 다른 파일을 삭제하지 않습니다.
- 매 삭제 직전 파일 속성과 경로를 재검사합니다. 변경된 파일은 제외합니다. 폴더 구조를 다른 프로세스가 동시에 바꾸지 않도록 운영 권한을 관리해야 합니다.
- 정책 조회·공간 조회 실패 시 삭제를 중단하고 다음 주기에 재시도합니다. 후보가 없거나 회당 제한에 도달해 공간이 부족하면 부족 이벤트를 남깁니다.
- 자동 정리 일시 중지는 삭제 대상 기준의 사용 체크를 해제합니다. 진행 중인 점검은 이미 조회한 정책으로 진행될 수 있습니다. 즉시 중지가 필요하면 서비스를 정상 종료하십시오.

## 이력 확인

자동 작업의 수행자는 `SYSTEM`, 수동 작업은 로그인 사용자입니다. 로그/이벤트 화면의 이벤트 유형 필터에 다음 항목을 추가했습니다.

| EVENT_TYPE | 의미 |
| --- | --- |
| STORAGE_DELETE_REQUEST | 파일 삭제 직전 요청 기록 |
| STORAGE_DELETE_SUCCESS | 파일 삭제 완료 |
| STORAGE_DELETE_FAIL | 파일 삭제 실패 |
| STORAGE_DELETE_SKIPPED | 보호·경로·변경 등의 이유로 제외 |
| STORAGE_CLEANUP_DONE | 자동 정리 후 공간 확보 |
| STORAGE_CLEANUP_FAIL | 정책 조회·공간 조회·정리 처리 실패 |
| STORAGE_SPACE_LOW | 정리 후에도 공간 부족 또는 보관 정책 없음 |

요청·결과 메시지의 `op` 값으로 같은 파일 작업을 연결할 수 있습니다. DB 장애 중에는 기존 감사 저널(`logs/audit-pending`)에 먼저 저장하고 DB 복구 후 재전송합니다. 저널에 요청조차 저장할 수 없으면 삭제를 시작하지 않습니다. 파일 삭제와 DB 저장은 단일 트랜잭션이 아니므로 삭제 직후 프로세스·디스크가 중단되면 요청만 남을 수 있습니다. 이 경우 실제 파일 존재 여부를 대조해야 합니다. 이력 저장 실패를 파일 삭제 실패로 오인해 같은 파일을 복원하지는 않습니다.

```sql
SELECT id, actor_user_id, event_type, message, reg_dt
FROM public.tb_event
WHERE event_type LIKE 'STORAGE_%'
ORDER BY reg_dt DESC, id DESC;
```

주기 점검 수치는 WebService 파일 로그의 `STORAGE_SPACE_CHECK`로 확인합니다. 가용 공간 부족은 이 단계에서 이벤트로 기록하며 장비 알람(`tb_alarm`)은 별도로 생성하지 않습니다.

## 안전한 시험

1. 실운영 수신 폴더가 아닌 별도 시험 폴더에 오래된 dump, 최근 dump, mp4, log, 하위 폴더의 dump를 준비합니다.
2. 보관 기간보다 오래된 시험 dump의 수정 시각을 설정합니다. 실제 수신 자료의 수정 시각은 변경하지 마십시오.
3. 시험 폴더에만 적용되는 가용 공간 기준으로 부족 조건을 만들고 자동 정리를 활성화합니다. 실제 디스크를 채우지 않아도 최소 여유 공간 기준을 현재 여유 공간보다 크게 설정하면 시험할 수 있습니다.
4. 첫 점검 후 오래된 직계 dump만 삭제되고 나머지 파일이 남는지, `tb_event`에 요청·결과가 기록되는지 확인합니다.
5. 정상 공간 기준으로 복원한 뒤 오래된 dump도 삭제되지 않는지 확인합니다. 시험 종료 후 자동 삭제를 비활성화하거나 운영 기준으로 되돌립니다.

자동 테스트는 운영 DB 없이 임시 폴더, 모의 디스크 공간, H2를 사용합니다. 전체 Spring Boot 서버를 시작하는 테스트는 아니며, 실제 폴더·계정 권한과 운영 DB 연결은 적용 후 별도 확인해야 합니다.
